# 第三阶段：预测页 AI 生命周期与右栏布局修复

## 问题根因

系统只创建一个共享的 `#ai-face` 节点，正常情况下该节点挂载在持久存在的 `#screen-content` 中。进入影响等级分析页时，旧实现将这一共享节点直接移动到页面自身的 `data-impact-ai-face-slot` 内。路由切换时，页面渲染器通过替换 `#app` 内容销毁旧页面，因此同时销毁了仍停靠在页面子树中的共享 AI 节点。

这既解释了进入预测页后 AI 异常，也解释了离开预测页后其他页面无法恢复：恢复逻辑只能重新定位仍存在的节点，不能找回已经随页面 DOM 一起销毁的节点。

## 修复方案

- 在共享 AI 模块中增加明确的模式切换接口：普通悬浮模式与影响分析侧栏模式。
- 每次路由页面替换前，先将共享 AI 归还到持久外壳，再执行页面内容替换。
- 影响分析页渲染完成后，将同一个共享实例停靠到右侧卡片，不创建第二个 AI。
- 侧栏插槽只负责承载共享节点，不拥有节点生命周期；页面离开时不删除共享 AI。
- 保留路由令牌校验，避免旧页面的异步动画帧在新页面上执行过期切换。

## 右栏布局

- 桌面端主区域采用约 70% / 30% 两栏布局。
- 右栏为内容区内的 `sticky` 卡片，不使用覆盖页面的固定定位。
- AI 表情区常规高度为 168px；低高度窗口压缩为 132px。
- 对话内容改为一个连续消息列表，消息使用轻量分隔线，不再显示多个割裂的大面板。
- 消息列表仅在内容超出时内部滚动；页面主体仍由共享内容区负责滚动。
- 用途边界集中在右栏底部，删除页面底部重复的大型免责声明。
- 800px 以下改为单列、取消 sticky，保持自然文档流。

## 浏览器验证

使用实际开发地址 `http://127.0.0.1:5173` 完成以下检查：

- 总览、查询、分析中心、AI 问询、影响等级分析和管理端页面均存在且仅存在一个 `#ai-face`。
- 连续进入和离开影响等级分析页 5 次；每次进入后父节点为侧栏插槽，离开后恢复到 `#screen-content`。
- 每次切换后的 `hidden`、`display`、`visibility`、`opacity` 和停靠 class 均符合当前模式。
- 输入选项失败和预测请求失败时，AI 仍显示在侧栏。
- 完成一次真实预测后，Low、Moderate、Severe 三类模型输出概率正常显示，AI 仍为唯一实例。
- 1440×900、1280×600、960×600 三种尺寸均可滚动到底部；右栏没有遮挡底部状态栏，消息区使用独立的内部滚动。
- 浏览器 Console 无错误。

机器可读结果见 `第三阶段_预测页AI生命周期浏览器验证.json`，三种尺寸的页面截图见同目录 `impact-ai-*.png`。
