# 第三阶段：实际环境选项加载与全站导航修复报告

## 1. 实际故障复现与根因

本轮开始时，`127.0.0.1:5173` 与 `127.0.0.1:8000` 仍由上轮手工启动且未退出的独立进程提供服务。与此同时，两个更早启动的 Node 进程仍占用 `localhost:5173` 的 IPv6 路径。因此同一台机器实际上存在两套页面：`127.0.0.1:5173/api/impact-options` 返回 JSON，而用户当前标签页使用的 `localhost:5173/api/impact-options` 返回 HTTP 200、`text/html` 和 `index.html`。这就是自动化验证成功而实际标签页失败的直接原因。

停止全部旧进程后，从零执行 `npm run dev` 又稳定复现第二个问题：项目机器只有系统 Python 3.14，原 `scripts/dev.mjs` 只执行 `python --version` 判断解释器可用，却没有验证 NumPy、pandas、scikit-learn、SciPy、joblib 和冻结推理模块。Python API 随后因 `ModuleNotFoundError: No module named 'numpy'` 退出。

因此，上轮浏览器成功实际依赖临时手工指定的 Python 运行时，并没有证明默认启动命令可用。用户实际页面是 Vite 本地开发页面；当只运行前端或 Python API 启动失败时，`GET /api/impact-options` 会被 Vite SPA fallback 接管，表现为 HTTP 200、`text/html` 和 `index.html`。前端于是进入选项阻断状态。

## 2. 完整开发环境

项目现使用 `.venv` 作为明确的 Python 环境。`npm run dev` 执行顺序为：

1. 验证解释器能够导入全部冻结推理依赖和推理服务；
2. 启动 `127.0.0.1:8000` Python API；
3. 轮询 `/api/health`，确认 JSON 就绪；
4. 只有健康检查通过后才启动 `127.0.0.1:5173` Vite；
5. 在 `::1:5173` 建立无缓存 307 别名，将用户访问的 `localhost` 原路径完整转到唯一的 IPv4 Vite；
6. 只有 `localhost` 别名也能返回完整 HTTP 响应后，命令才报告就绪；
7. 任何子进程退出都会终止整套环境。

Windows 下 Python 和 Vite 子进程均增加父进程生命周期绑定。测试中强制结束编排父进程后，5173 与 8000 均停止监听，没有留下可被下一轮误复用的 API。

使用非法 API 端口模拟启动失败时，命令以非零状态退出，测试前端端口没有启动。

## 3. Vite Preview 与 Vercel 边界

`npm run preview` 现在也通过同一编排器先启动 API，健康检查通过后再启动 `127.0.0.1:4173` 的 Vite Preview，并为 `localhost:4173` 建立相同的别名。Preview 浏览器验证从 `http://localhost:4173` 进入，选项和预测接口均返回 HTTP 200 JSON，并完成真实预测。

仓库当前不存在 `.vercel/project.json`，没有可识别的已链接 Vercel Preview；本轮没有正式部署，也没有对远程预览或生产环境作成功声明。`api/impact-options.py` 符合现有 Vercel Python Function 文件约定，部署所需模型副本和冻结辅助数据位于未被 `.vercelignore` 排除的 `ml_inference/frozen_assets`，但仍需在实际部署产生后单独验证。

## 4. 导航与页面入口

所有用户端和管理端子页面现在只显示一个共享“主菜单”按钮，目标为实际顶层路由 `#/start`。不再显示“用户端”“管理端”中间层或当前页面文字。共享导航使用原生按钮、`aria-label` 和 `focus-visible`。

用户总览、数据分析和 AI 问询页面会在异步数据完成后整体重绘。该行为曾移除共享导航，本轮在共享组件内部加入单例 `MutationObserver`，页面重绘后只补回一个主菜单按钮，不在各页面增加临时实现。

管理模型页面的代码和 `admin/models` 路由从未丢失，Dashboard 中的模型入口也仍存在。顶层管理入口消失的原因是主菜单过去对非管理员完全不渲染该入口；现在普通用户可看到带 `ADMIN ONLY` 的锁定入口，管理员看到可访问入口，权限守卫保持不变。用户总览原先确实漏掉影响等级分析入口，本轮已经补回。

## 5. 全站 VAULT-0 AI

项目继续复用唯一的 `#ai-face` SVG 组件、状态逻辑、眼睛与拖动逻辑。主菜单、全部用户端页面、全部管理端页面和模型页均显示同一个 AI，不复制 HTML、不重复初始化。普通页面使用可拖动悬浮模式；影响等级分析页将同一组件停靠到右侧栏并禁用拖动。路由离开后组件重新回到共享悬浮模式。

AI 动画现尊重 `prefers-reduced-motion`。素材是内建 SVG，不依赖外部图片加载。

## 6. 影响等级分析布局

桌面采用左右两栏：左侧包含表单、说明、提交操作和结果；右侧为 sticky VAULT-0 区域，包含原 AI 表情、可内部滚动的消息列表和用途边界。消息按 loading、ready、incomplete、analyzing、success、failure、blocking_error 和 retrying 追加，最多保留 12 条。窄窗口改为上下布局，低高度桌面压缩 AI 展示区。

选项失败时下拉框改为明确的“载入失败”，不会停留在“正在重新加载”。收到 `text/html` 时，页面明确提示需要通过 `npm run dev` 启动完整环境。真实浏览器模拟首次 503 后，重试第 2 次成功恢复国家列表。
